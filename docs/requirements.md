# Vim操作習得ドリル 要件定義書

## 1. 背景とビジョン（設計思想）

- **身体で覚える操作体系**: Vimの真価は、思考と編集が直結する「指先の反射」によって発揮される。操作量・反復回数に習得率は比例する。
- **脱・初級者から超高速操作へのステップアップ**: `vimtutor` を一通り終えた段階のユーザーが、実務で真に武器となる「無駄のない最短の編集ストローク」を身体に叩き込める環境を提供する。
- **第一目標**: 開発者自身が本ツールを用いて最短で「Vimマスター」になること。

---

## 2. 対象ユーザー

- **前提スキル**: 基本的なモード遷移や移動（hjkl等）、単純な挿入・削除など `vimtutor` レベルの基本操作を理解しているユーザー。
- **ニーズ**:
  - 実践的なキーコンビネーション（テキストオブジェクト、ドット反復、行内検索、マクロなど）を使いこなせていない。
  - ついつい慣れた手癖（hjkl連打やBackspace連打）で非効率な編集をしてしまう。
  - 普段の開発で使う実用コード（C#, Python, C, XML, Markdownなど）に近い文脈で練習したい。
  - 自身のカスタマイズ環境をそのまま維持しながら練習したい。

---

## 3. システムゴール

1. 各自の普段のVim/Neovim環境内において、一問一答形式のドリルを高速に反復できる体験を提供する。
2. 提示された初期テキストを目標テキストへ効率よく変換するプロセスを通じ、より少ない打鍵数での編集感覚を身体に刷り込む。
3. ユーザーの入力キー列と模範解答を対比可視化し、無駄な打鍵や手癖を自覚・矯正できるフィードバックサイクルを回す。

---

## 4. 機能要件

### 4.1 利用形態・環境
- **エディタ内完結**:
  - 普段利用しているVim/Neovim内から直接起動・終了できること。
- **各自の環境維持**:
  - ユーザー独自の設定、キーマッピング、導入済みプラグインがそのまま機能すること。
- **プラグインとしての導入容易性**:
  - 一般的なプラグインマネージャー（`lazy.nvim`, `packer.nvim`, `vim-plug` 等）から、リポジトリURLまたはローカルディレクトリを指定するだけで簡単にインストール・有効化できる標準的なプラグイン構造を持つこと。
  - 外部ランタイムや外部バイナリの事前ビルド・インストール（Node.js, Rust, Go等）を一切要求せず、Neovim環境のみでゼロセットアップで即座に動作すること。

### 4.2 ドリル出題とUI体験

#### 起動画面（テーマ選択）
- **無骨でシンプルなフローティングウィンドウ**:
  - コマンド（例: `:VimMaster`）実行時、背景のコード上に枠線とテーマ一覧のみを提示する軽量なポップアップを表示すること。
  - 進捗率や正解率などのゲーム的演出は排除し、選択して即座に練習に入れるミニマルな体験とすること。
- **適応型ランダム出題（弱点克服）**:
  - テーマ選択後は、該当テーマの問題がランダムに出題されること。
  - 画面上には表示しないが、裏側で「打鍵数オーバー率が高い問題」や「リセットした問題」などの苦手な問題の出現確率が自動的に高まる適応型の抽選ロジックを持つこと。

#### メインプレイ画面
- **完全プレーンな左右分割表示**:
  - 画面を左右に分割し、「左側にユーザーが実際に編集する作業バッファ」、「右側に目標テキスト（正解のプレビュー）」を並べて提示すること。
  - diff等の色付けや装飾は行わず、実戦と同じ「素のテキストを見比べる」認知負荷を保つこと。
  - 長文問題においても編集箇所を見失わないよう、左右の画面が連動してスクロール（`scrollbind` 相当）すること。
- **課題の明確性（ミッションと初期位置）**:
  - 問題開始時に、編集目的を端的に示す指示（ミッション）を提示すること。
  - 課題ごとに適切な初期カーソル位置を設定可能とし、即座に目的の編集を開始できるようにすること。
- **打鍵数のリアルタイムカウント**:
  - 画面下部に、現在のキーストローク数（打鍵数）をリアルタイムに表示すること。
- **キー操作の共存とカスタマイズ性**:
  - 問題を解いている最中は、ツールの独自ショートカットでVimの通常キー操作（移動、編集、Exコマンド等）をハイジャックしないこと。
  - 「最初からやり直す（Reset）」および「ドリル終了（Quit）」のキー操作を画面上に明示し、かつどのキーを割り当てるかはユーザー設定で変更可能であること。

### 4.3 判定フロー（明示的Submit方式）
- **手動判定（Submit）**:
  - 編集の途中で勝手にポップアップが出ないよう、ユーザーが「できた」と確信したタイミングでノーマルモードから明示的に判定アクション（デフォルト: `<CR>`、設定で変更可能）を実行する方式とすること。
- **不一致時（不正解）の挙動**:
  - 目標テキストと一致していない場合は、編集を妨げるポップアップは出さず、画面最下部等に静かに通知（`Not match yet` 等）を表示すること。
  - ユーザーはそのまま編集を続行でき、打鍵数カウントも継続されること。
- **一致時（正解・クリア）の挙動**:
  - 目標テキストと完全一致している場合、即座にリザルト画面を表示すること。

### 4.4 リザルト画面（手癖の可視化）
- **無骨なリザルトポップアップ**:
  - クリア時に画面中央にシンプルな枠線でリザルトを表示すること。
- **入力キー列と模範の対比可視化**:
  - 「ユーザーが実際に打鍵したキーシーケンス（Your Keys）」と、「模範の最短キーシーケンス（Ideal Keys）」を上下に対比して明示すること。
  - 移動のムダ（例: `h/j/k/l` の連打）や不要な打鍵を一目で自覚・反省できるようにすること。
- **スコアと解説の提示**:
  - クリア打鍵数、基準打鍵数（Par）、所要時間を表示すること。
  - 模範操作の意図やテクニック（なぜこのキーを使うと速いのか）の簡潔な解説を提示すること。

### 4.5 反復・リトライ体験
- **リザルト画面からの直感的操作**:
  - リザルト画面において、以下の操作を受け付けること：
    - **即時リトライ（`r`）**: 模範キー列を確認した直後、ワンキーで初期状態に戻り、覚えた最短手をその場で自分の指に上書き刷り込みできること。
    - **次の問題へ進む（`<CR>` / `n`）**: 次のランダム問題へテンポよく移行すること。
    - **終了（`q`）**: メニューに戻る、またはドリルを終了すること。

### 4.6 学習カリキュラム（出題スコープ）

#### 【基礎編】必ず習得すべきコア操作（Lv 1 〜 Lv 3）
Vimの操作体系を身体に叩き込み、無駄な打鍵をゼロにするための必修カリキュラム。
- **Lv 1: 行内移動・瞬発力（1〜3行）**
  - 単語移動（`w`, `b`, `e`, `ge`）
  - 行内ジャンプ・検索（`f`, `t`, `F`, `T`, `;`, `,`）
  - 基本クォート・括弧の編集（`ci"`, `da(`, `dw`, `s` 等）
- **Lv 2: 構造・テキストオブジェクト操作（5〜15行）**
  - ブロック・タグオブジェクト（`ci{`, `yap`, `cit`, `cat` 等）
  - ドット反復（`.`）による同一操作の繰り返し
  - 段落・関数単位の移動（`{`, `}`, `%` 等）
- **Lv 3: 複数行・一括編集（15〜30行）**
  - ビジュアル矩形選択（`<C-v>`）による一括挿入・削除
  - 検索反復ジャンプ（`/`, `?`, `n`, `N`）および `cgn`
  - インデント調整（`>`、`<`）、行結合（`J`）

#### 【実践編】長文高度編集・実務テーマ（Lv 4）
実際の開発コードや大量ログデータ（数十〜100行程度）を舞台に、高度な編集技法（マクロ・exコマンド・レジスタ等）を駆使して一網打尽にする応用カリキュラム。初期テーマとして以下を柱とする：
- **テーマ①: 実践コードリファクタリング**
  - メソッド分割に伴うコードブロックの移送（レジスタ）、関数シグネチャ変更の一括追従、変数名の一括変更（`cgn` や `:s`）、長大な条件分岐の整理など。
- **テーマ②: ログ解析・テキストデータ整形**
  - Webサーバーログやデバッグログ、スタックトレース、CSV/JSONデータからの情報抽出・整形。
  - グローバルコマンド（`:g/ERROR/`, `:v/.../d`）による不要行の一括削除、マクロ（`qq...q`）によるログフォーマットのTSV変換、正規表現置換（`:s`）による特定フィールドの抽出など。

#### 実践的プログラミング言語ドリル
- ユーザーが実務で扱う主要言語（C#, Python, C, XML, Markdown等）の構文構造を題材にした実践課題セット（各レベルに対応）：
  - Python: 引数の順序変更、辞書/内包表記の編集、インデント調整
  - C# / C: メソッドシグネチャ変更、波括弧ブロック編集、型宣言の修正
  - XML / HTML: `cit`, `cat` によるタグ・属性の高速書き換え
  - Markdown: リスト構造、テーブル、リンク書式の編集

#### プラグイン別専用コース（分離提供）
- 特定のプラグイン（`surround` 系プラグイン等）を前提としたドリルは、Vanillaコースと混在させず、独立した専用コースとして切り分けて選択・受講できるようにすること。

### 4.7 学習記録・進捗管理
- **学習履歴の保存**:
  - クリア済み問題、各問題の自己ベスト記録（打鍵数・時間）、トータルの練習打鍵数を永続化すること。
- **成長・練習量の可視化**:
  - ユーザーがこれまでに行った「総操作量（打鍵数）」および各課題の上達度を確認できること。

### 4.8 コンテンツ拡張性（テーマ単位の拡張）
- **ビルトインコースの提供**:
  - 導入後すぐに学習を始められる公式ドリルコース（基礎編・実践編）が用意されていること。
- **テーマ単位での階層的拡張性**:
  - **既存テーマへの問題追加**: 「ログ解析」や「Python」など、既存のテーマに新しい問題定義を自由に追加できること。
  - **新規テーマの追加**: ユーザーが独自の新しいテーマ（例: 「SQLクエリ最適化」「Gitコンフリクト解消」など）をファイル単位で自由に追加し、その配下に問題群を定義・受講できること。
  - 各テーマおよび問題定義はシンプルな宣言的フォーマット（LuaテーブルまたはJSON等）で記述可能であること。

---

## 5. 非機能要件

- **即応性（低レイテンシ）**:
  - 課題の切り替え、初期化、正誤判定、リトライが瞬時（体感遅延なし）に行われ、反復練習のリズムを一切妨げないこと。
- **安全性・独立性**:
  - ドリルの実行やリトライによって、ユーザーが普段開いている作業バッファや実ファイルが破壊・汚染されないこと。
- **可搬性**:
  - 特定のOSやターミナル環境に依存せず、Vim/Neovimが動作する環境で機能すること。
